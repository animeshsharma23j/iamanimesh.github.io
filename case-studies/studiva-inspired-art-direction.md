# STUDIVA-Inspired Art Direction For UnitX And BuildX

## Reference Takeaway

The STUDIVA reference works because it feels like a designed presentation, not a blog post. It uses oversized product typography, soft gradient canvases, floating pills, realistic phone mockups, wide white space, and calm process boards.

For UnitX and BuildX, use the same presentation rhythm while changing the brand world:

- UnitX should feel fast, premium, intelligent, and everyday-useful.
- BuildX should feel precise, structured, technical, and job-site trustworthy.

Do not copy STUDIVA's exact colors, phone screenshots, education positioning, icons, or section graphics. Borrow the pacing, spatial system, and softness.

## Shared Layout System

### Canvas

- Behance image width: 1400-1600 px.
- Use tall vertical boards, each designed as a standalone slide.
- Background: soft off-white or near-black tinted canvas, with gentle gradients.
- Keep generous margins. The reference leaves large quiet areas around content.
- Use one main visual idea per board.

### Type

- Big display headlines with one tinted word.
- Supporting copy should be short and calm.
- Use small labels and pill tags instead of dense paragraphs.
- Favor sentence-case section titles.

### Components

- Rounded pill tags for categories, tools, and feature labels.
- Floating note cards for insights or user jobs.
- Timeline columns with thin dotted or hairline dividers.
- Comparison matrices with pill headers and soft check indicators.
- Device mockups as the main proof of product quality.
- Large ghosted product wordmark behind the hero device.

### Motion In The Static Layout

Create visual energy through:

- angled floating cards
- overlapping phones
- large translucent wordmarks
- staggered pills
- curved or diagonal flows
- soft shadows under device mockups

## UnitX Direction

### Palette

Use a premium smart-utility palette:

- Background: charcoal black, soft lavender black, or misted off-white.
- Accent 1: electric cyan.
- Accent 2: warm amber.
- Accent 3: soft violet-pink for Behance-style pills.
- Text: near-white on dark boards, charcoal on light boards.

### Hero

Create a hero board similar in rhythm to STUDIVA:

- Large ghosted `UNITX` wordmark across the background.
- One phone-in-hand or angled iPhone mockup showing Smart Convert.
- Pills: `UI/UX Design`, `iOS Utility`, `AI Input`, `Watch App`.
- Year: `2026`.
- Tiny tool badge: `SwiftUI`, `StoreKit`, `Watch`.

Suggested headline:

**UnitX - Smart Unit Converter**

Suggested subline:

Type it. Say it. Scan it. Convert it.

### Process Boards

Use these STUDIVA-style boards:

1. **Overview / Project Info / Services**
   Three-column text panel with short copy.

2. **Project Timeline**
   Four phases: Product Strategy, UX Design, Implementation, Launch Prep.

3. **Competitive Analysis**
   Compare Manual Converter, Calculator App, Currency App, UnitX.
   Rows: Natural input, Camera scan, Voice input, Watch companion, Favorites/history.

4. **User Jobs**
   Angled floating cards for Traveler, Cook, Shopper, Student, Worker, Repeat User.

5. **Problem Statements**
   Light note cards showing setup friction: category, unit, value, repeat setup.

6. **Product Map**
   Pills flowing from Type, Voice, Camera, Manual into Result, Save, Replay, Watch.

7. **Final UI**
   Device screens for Smart Convert, Manual Converter, Camera Scan, Favorites, Watch.

8. **Design System**
   Swatches, typography, cards, result chips, accent palette.

9. **Reliability**
   Small QA board about smart-to-manual handoff, scan uncertainty, currency availability, sync.

## BuildX Direction

### Palette

Use a blueprint editorial palette:

- Background: pale blueprint white, cool grey, or dark blue-black.
- Accent 1: vivid blueprint blue.
- Accent 2: safety green for correct/calculated states.
- Accent 3: warm construction yellow used sparingly.
- Text: deep navy or clean white depending on board.

### Hero

Use STUDIVA's hero rhythm, but make it architectural:

- Large ghosted `BUILDX` wordmark across the background.
- Central iPhone mockup showing the calculator.
- Secondary screens for Home Tools and Concrete/Rafters behind it.
- Pills: `UI/UX Design`, `Construction App`, `Calculator`, `SwiftUI`.
- Year: `2026`.
- Small tool badge: `BuildXCore`, `SwiftUI`, `QA`.

Suggested headline:

**BuildX - Construction Calculator**

Suggested subline:

Exact fractions and trade tools for the field.

### Process Boards

Use these STUDIVA-style boards:

1. **Overview / Project Info / Services**
   Three-column intro with concise context.

2. **Project Timeline**
   Four phases: Domain Mapping, Calculator UX, Trade Tools, QA.

3. **Competitive Analysis**
   Compare Generic Calculator, Construction Calculator, Spreadsheet, BuildX.
   Rows: Fractions, history, trade tools, explainers, reusable results.

4. **User Jobs**
   Floating cards for Carpenter, Builder, Remodeler, DIY User, Repeat User.

5. **Problem Statements**
   Note cards around rounding mistakes, unit switching, waste factors, and code constraints.

6. **Tool Architecture**
   Calculator at center, with Layout & Framing and Materials branching around it.

7. **Final UI**
   Device screens for Calculator, Home Grid, Rafters, Concrete, Explainer, History.

8. **Design System**
   Blueprint palette, numeric typography, cards, keypad, tool badges.

9. **Calculation Trust**
   Board showing `BuildXCore`, tests, unit conversion, formulas, and handoff to calculator.

## Behance Board Checklist

For each final post, produce:

- Cover hero board
- One-line product statement
- Overview and info panel
- Timeline panel
- Competitive or opportunity matrix
- User jobs or research cards
- Product map
- Core flow board
- Final UI screen board
- Design system board
- Trust or QA board
- Reflection closing board

## Copy Style

Keep the copy airy:

- 1 headline per board
- 1 short paragraph or 3-5 bullets maximum
- Use labels for details
- Let screenshots and diagrams do most of the work

## Visual Production Notes

- Export boards as PNGs for Behance.
- Use real app screenshots where possible.
- If screenshots are not final, use high-fidelity recreated mockups, but avoid showing impossible states.
- Keep side annotations short.
- Make every board readable at Behance feed width.
